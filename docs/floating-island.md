# 悬浮岛（悬浮窗方案）

> 实现：`sample-timetable/src/main/kotlin/dev/dpvoliin/islandtimetable/IslandOverlay.kt`

## 为什么需要它

在 vivo 上，**两条正统路子都实测封死了**（详见 [oem-notes.md](oem-notes.md)）：

| 路子 | 结果 |
|---|---|
| Android 16 标准 API（`ProgressStyle` + `requestPromotedOngoing` + `shortCriticalText`） | 系统 `canPostPromotedNotifications() = false` → 只给白名单（合作方）放行 |
| 厂商私有字段（`notification.superx.*`，按 vivo 官方技术规范塞） | **被系统剥离**，读回来一个都不剩 |

所以对不放行的机型，只剩「自己画一个」这条路。

## 是什么 / 不是什么

**是**：
- 一个 `TYPE_APPLICATION_OVERLAY` 悬浮窗，在**状态栏下方**画一个药丸：进度环 + 课程名 + 剩余分钟
- 任何 Android 8+ 都能用，不依赖任何厂商能力、不需要任何准入、不需要 root
- 跟随真实上课倒计时刷新，呼吸描边；点它回到 App

**不是**：
- ❌ 不是「钻到摄像头挖孔里的原生岛」—— 那需要系统级权限，只有系统应用/合作方能做
- ❌ 不是系统通知，锁屏上不会出现，也不会进通知栏
- ❌ 不需要「显示在其他应用上层」以外的任何特殊权限（但那个权限**必须**用户手动授予）

> 一句话：**它是「看得见的替代品」，不是「伪装成系统的假货」。** 这条边界我们在 UI 文案里也直说。

## 需要用到的技术点

| 点 | 做法 |
|---|---|
| 窗口类型 | `WindowManager.LayoutParams.TYPE_APPLICATION_OVERLAY` |
| 权限 | `SYSTEM_ALERT_WINDOW`，检查 `Settings.canDrawOverlays()`，跳 `ACTION_MANAGE_OVERLAY_PERMISSION` |
| 定位 | `gravity = TOP or CENTER_HORIZONTAL`，`y = 状态栏高度 + 6dp` |
| 挖孔 | `layoutInDisplayCutoutMode = LAYOUT_IN_DISPLAY_CUTOUT_MODE_SHORT_EDGES`（否则部分机型会把窗口挤下去） |
| 不抢焦点 | `FLAG_NOT_FOCUSABLE or FLAG_NOT_TOUCH_MODAL or FLAG_LAYOUT_IN_SCREEN`（仍然可点击） |
| 自绘 | 自定义 `View.onDraw`：圆角矩形 + `drawArc` 进度环 + 呼吸描边（`postInvalidateDelayed(40)`，约 25fps） |
| 生命周期 | 目前由 Activity 持有；**下一步**改成前台服务（`specialUse`），这样划掉 App 后岛还在 |

## 自动路由：识别机型后自动选路（不需要用户操心）

**原则：系统实时通知能用就用它，用不了才启用悬浮岛。** 判定在库里的 `IslandRouter.resolve()`（`liveupdates/IslandRoute.kt`）：

| 优先级 | 条件 | 结果 |
|---|---|---|
| 1 | `canPostPromotedNotifications() == true` | `STANDARD` —— 系统自己渲染，**不启用悬浮岛** |
| 3 | 以上都不满足（vivo 等） | `NONE` —— **自动启用悬浮岛**（缺悬浮窗权限时静默跳过，能力卡片里提示去授权） |

代码里的用法（`MainActivity.autoShowOverlayIfNeeded()`）：

```kotlin
if (islandRoute.isReal) {
    islandOverlay?.hide()          // 实时通知够用，别画蛇添足
} else if (autoIsland && overlay.canShow()) {
    overlay.show(name, "还有 N 分", progress)
}
```

- 路由结果缓存在 `islandRoute`，**每秒的倒计时刷新不会重复探测**（探测本身也是纯读系统状态）。
- UI 上有开关「自动选择推送方式」，默认开；关掉后只能手动点「悬浮岛预览」。
- 能力探测卡片会直接显示：**当前推送通道 + 悬浮岛权限状态**，用户一眼知道自己在走哪条路。

## 和系统实时通知的共存规则（重要）

一条明确的分工，避免"两个岛打架"：

| 情形 | 悬浮岛怎么办 | 现状 |
|---|---|---|
| **本应用**的实时通知被系统放行（`IslandRouter.isReal`） | **不显示**（就算手动开过也自动收起） | ✅ 已实现 |
| **别的 App** 的实时通知正在显示（外卖/打车的进行中通知…） | 两者都在顶部中间，会**短暂重叠** | 🔶 v0.1.8 的缓解：**紧凑模式**（默认开，只显示进度环 + 少数字），横向占位压到最小 |
| 系统岛之后消失 | 无需处理 | — |

### 位置：只能贴状态栏**下沿**（层级硬约束）

vivo（Android 16）实测：**应用悬浮窗的层级低于 SystemUI 的顶部信息栏**。后果：

- 药丸画到状态栏那一行 → 被状态栏压住（顶部信息栏盖在上面）
- 系统的实时通知属于 SystemUI，层级也在我们之上 → 一来就把我们的药丸**挡住**

> 这不是参数没调好：普通应用拿不到比 SystemUI 更高的窗口类型
> （`TYPE_STATUS_BAR_*` / `TYPE_SYSTEM_*` 都是系统应用专用）。同类项目也都是绕着走 ——
> 画"屏幕边缘光带"而不是顶部区域，大概率就是同一个原因：顶部那块不属于我们。

**所以本项目的位置策略**：默认用**贴右边缘**的形态（方案 2，见下），备选是「紧贴状态栏下沿、居中、30dp 高」。
**不追求"钻进挖孔"** —— 那件事属于系统/合作方。

### 形态与交互（0.1.11 起：**只保留侧边**）

**顶部形态已删除** —— 钻不进状态栏那一行（层级低于 SystemUI），留着只是鸡肋。

| 状态 / 操作 | 表现 |
|---|---|
| 展开 | 贴边竖卡 34×66dp：环形倒计时，圈内是剩余分钟；`✓` 表示即将下课 |
| **自动收起** | 展示约 **3 秒**后自动缩成贴边**小按钮 16×34dp**（内含一条竖线表示进度） |
| 点小按钮 | 再展开 3 秒（可反复） |
| 点小卡（展开时） | 回到 App |
| **长按** | 彻底隐藏**本次**（下一次开始上课自动回来） |
| **拖动** | 任意移动，松手**自动吸附到最近的左/右边缘**；吸附侧与竖直位置写入偏好，下次沿用 |

**离屏幕边缘的距离是动态算的**（0.1.15 起）：

- 基础间隙 **20dp**（`EDGE_GAP_DP`，从 8dp 提上来的）
- 运行时与**系统侧滑手势区宽度**取较大者：`WindowInsets.systemGestureInsets.left/right` + 4dp 余量
- 左右各算一份（有些 ROM 两侧不对称）

> 起因：用户实测「贴着右边想拖动卡片时，动作经常被判成**返回手势**」。
> 与其猜一个固定边距，不如直接问系统手势区有多宽，把卡片放到它外面。
> 顺带好处：三键导航（手势区为 0）时自然回到 20dp，不会平白多出一大段空隙。
- 两侧都不做"藏一半到屏幕外"—— 左侧那样会裁掉小按钮（0.1.12 修过）。

### 动画（0.1.12 起；0.1.14 修掉「白框散开」）

| 时机 | 动画 |
|---|---|
| 入场 | 窗口从屏幕外**滑**到贴边位置（`ValueAnimator` 逐帧 `updateViewLayout`）240ms + 0.88 → 1 缩放淡入 |
| 收起 | 先缩到 0.5 淡到 0.6（170ms），换成小按钮后再从 0.7 长到 1（230ms） |
| 展开 | 先缩一下（130ms），换回小卡后从 0.62 长到 1（250ms） |
| 拖动 | 起手「捏小」到 0.96 + 淡化 0.94；松手回到 1 |
| 吸附 | **整窗滑动**到目标 x（240ms，`DecelerateInterpolator`） |
| 点按 | 压到 0.88（90ms）→ 弹回 1（170ms） |
| 呼吸 | 描边透明度随 `sin` 波动，约 25fps（`postInvalidateDelayed(40)`） |

#### 两条铁律（0.1.14 实测踩坑）

1. **缩放/位移不得越过静止值**。窗口是 `WRAP_CONTENT`、尺寸**正好等于卡片**，所以任何 `scale > 1`
   或 `translation != 0` 都会让绘制被窗口**裁掉** —— 表现就是「外围白框断开/散开」；动画被 `cancel`
   时会停在中间值，所以"点一下才恢复"。现在：拖动反馈改成「捏小到 0.96」、入场/展开只用「小 → 1」的
   单调放大，且**每次起新动画前先 `resetTransform()`** 复位 scale/alpha/translation。
2. **要移动就移动窗口本身**。吸附原用 `translationX` 反向补偿（视觉对，但内容越出窗口被裁）；
   现在用 `ValueAnimator.ofInt(from, to)` 逐帧改 `params.x` + `updateViewLayout`，窗口整体滑动不裁边。

#### 自动收起改成看门狗（0.1.14）

原来是一次性 `postDelayed` 定时器：任何 `removeCallbacks`（拖动开始/隐藏）之后没重排，就**再也不收了**
—— 实测现象："点过岛之后就不隐藏了"。

现在记 `lastInteractionAt`，由**看门狗**每 400ms 检查：`未收起 && now - lastInteractionAt >= 3s` → 收起。
触摸 DOWN、拖动 MOVE、松手、点按、展开、内容刷新都会续期，所以拖动中不会被打断，交互后必定 3 秒收起。

### 已修的两个「自动隐藏」bug

1. **收起后看不见的区域还在吃点击** —— 窗口原本一直是 34×66dp，收起只换了绘制内容，
   那块透明区域照样拦截触摸（点在它上面没反应）。现在**收起时窗口一起缩到小按钮尺寸**（`requestLayout` + 重新贴边）。
2. **左侧吸附后收起"几乎全被遮住"** —— 旧版把 8dp 藏到屏幕外来"贴边"，左侧时窗口从 −8dp 开始，
   而小触点仅 12dp 宽 → 只剩 4dp 可见。现在两侧都留 8dp 间隙、窗口不越界。

实现要点：

- 贴边位置按**当前尺寸**计算（`currentWidthPx()`），所以收起/展开后都会重新贴好边
- 竖直位置默认 42%，限制在 8% ~ 85%；拖动时实时 `updateViewLayout`，松手吸附并持久化
- 触摸：`ACTION_DOWN` 起 550ms 长按计时；位移超过 4dp 视为拖动并取消长按；拖动结束后重新开始收起计时

### v0.2：自适应让位（正面解决重叠）

申请「通知使用权」（`NotificationListenerService`）→ 检测顶部是否有活跃的实时通知 →
**有就让位：把悬浮岛自动隐藏**（不是下移），系统岛消失后再浮回来。

> 为什么现在不做：不申请通知使用权就**读不到**别的 App 的通知状态，没有别的可靠信号；
> 而这个权限不轻，应该做成用户可选开关（本项目原则：能不加的权限先不加）。

## 已知限制与后续

1. **保活**：现在窗口挂在 Activity 进程上，划掉 App 就没了 → v0.2 改成前台服务。
2. **位置**：只能贴状态栏下方；不同机型状态栏高度/挖孔位置差异需要用 `WindowInsets.getDisplayCutout()` 精细适配。
3. **交互**：目前点击 = 回到 App；后续加长按收起、双击展开大卡。
4. **省电**：呼吸动画约 25fps，只在显示时运行；后续给一个「静止模式」开关（本项目一贯原则：省电默认关）。
