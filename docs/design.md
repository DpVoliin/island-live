

## v0.3：让课表真的能用（周次切换 / 下一节课 / 上课提醒）

导入只是"把数据弄进来"，真正让人天天打开的是这三件事 —— 而且**都不依赖任何厂商放行**（全机型可用）：

### 1. 周次切换（`DemoTimetable.viewWeek`）

数据层本来就按周存（`Course.weeks`），之前只按"当前周"过滤，导致**导入的"单周课 / 前 8 周结课"看不见**。
现在界面可以翻周（`＜` `＞`，点周次徽标回到本周），网格按 `viewWeek` 过滤；
而"下一节课 / 上课提醒"仍然按**真实当前周**算（`coursesToday()` / `upcoming()`），不受翻周影响。

### 2. 下一节课（`DemoTimetable.upcoming()`）

**跨天**找最近一节课：逐天看"那天是第几周"，再取那天在该周次下真实存在的课，用节次开始时刻和现在比 ——
所以跨周、单双周、结课都自然正确。主页空闲态显示：周几 + 第几节 + 课程 + 教室 + "还有 1 天 2 小时"。

### 3. 上课提醒（`ClassReminder` + `ReminderReceiver`）

设计要点：

- **永远只排最近一节课的一个闹钟**，响完立刻排下一节 —— 不会像"批量排整学期"那样越排越多，
  课表变了只要重排一次就不会残留过期闹钟
- **精确闹钟**：Android 12+ 需用户授权「闹钟与提醒」（`canScheduleExactAlarms`）；没授权自动退化为
  不精确闹钟（可能晚几分钟），界面上给出引导文案，点一下跳授权页
- **开机重排**：闹钟不跨重启存活，`ReminderReceiver` 同时监听 `BOOT_COMPLETED` 与
  `MY_PACKAGE_REPLACED` —— 不重排的话用户重启一次手机、提醒就永久失效
- 通知里显示"10 分钟后上课 · 高等数学 · 3教305 · 第1-2节"，点击回到 App
- 只提醒**当前周次真实存在**的课（借 `upcoming()` 的周次过滤），所以单双周、结课都不会误报

权限：`SCHEDULE_EXACT_ALARM`（可退化）、`RECEIVE_BOOT_COMPLETED`；不需要任何厂商特殊权限。

## v0.4：界面重构（主屏做减法 + 侧栏）

**目标**：主屏只放"天天要看的"，其余收进左侧栏；**测试/排障类功能 v0.12 起已整体移除**（结论留档在 docs 里）。

| 位置 | 内容 |
|---|---|
| **主屏** | 下一节课卡（大字课程 + 剩余时间 + 进度条）· 本周课表卡（翻周 + 网格）· 上课提醒卡 |
| **侧栏** | 通知（开启 / 关闭通知）· 设置（**主题** / 通知设置 / 上课提醒震动 / 上课自动静音）· 悬浮岛（预览 + 自动启用开关）· 课表（导入 / 导出备份 / 周次修正 / 教务直连）· 后台与通知存活 |

- 抽屉用 `DrawerLayout`（appcompat 已传递依赖，**不需要新增依赖**）+ 普通 `LinearLayout` 作内容
  （不用 `NavigationView`，样式完全自己控制，才好统一暗色与间距）
- **修掉一个既有视觉 bug**：Android 16 起强制 edge-to-edge，原布局没处理 insets →
  顶部「岛课表」标题被状态栏文字压住。现在用 `ViewCompat.setOnApplyWindowInsetsListener`
  给主内容与侧栏分别留出系统栏空间（顺带修了底部导航条遮挡）
- 动作型按钮点完**自动收起侧栏**（开关类不收起，方便连拨）；`onPause` 也收起
- 视觉规范：统一 20dp 圆角卡片 + 1px 描边 + 无阴影；强调色只出现在"还剩多久"和选中项；
  主屏零按钮噪音（唯一的按钮是顶栏的 ☰）

### 搬动视图的机械核对（重要）

把控件搬进侧栏最大的风险是**代码引用了一个布局里不存在的 id** —— `findViewById` 返回 null，
赋值给 `lateinit` 字段会在启动瞬间崩。所以提交前必做一步：

```
把 Kotlin 里所有 R.id.* 抽出来，逐个确认布局里存在（本次 42 个全中）
```

本次就是靠这一步抓到漏掉的 `tvNowState`（搬布局时忘了加回）。同样的核对也适用于
「引用不存在的 drawable / color / style / string」——一起放进 `tools/static-check.py` 的同类检查里。
